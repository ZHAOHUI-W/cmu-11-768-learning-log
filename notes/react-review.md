# ReAct · 首轮集中答题复盘

日期：2026-11-03。依据原论文第 3–8 页、Table 1–4 及第 10 页伦理说明。与工程补充区分，不把抽样结果或作者猜测当成普遍保证。

## 我的回答要点

1. Thought 由模型产生；对 Action 的描述混合了动作指令和工具返回结果；Observation 理解为行动后的环境状态。CoT 只推理，Act-only 只行动。
2. Search 理解为返回搜索前五个结果的第一个，有歧义则全部返回；Lookup 返回页面内下一个包含字符串的句子；Finish 提交答案。搜索失败后改写查询，多次失败返回空。
3. HotpotQA 是多跳检索，指标理解为检索准确率；FEVER 是事实验证；ALFWorld 是家庭具身长程任务；WebShop 理解为真实购物，指标为买对成功率。
4. 正确认识 ReAct 并非全面优于 CoT，HotpotQA 上低于 CoT；不清楚幻觉如何评价。理解两者可以切换互补，但反向切换条件只说到判断是否需要检索。
5. 正确认识 few-shot 不更新参数、finetuning 使用模型轨迹。提出重复 Thought/Action、检索恢复与长上下文问题，并询问循环是否与贪心解码有关。

## 1. 信息流

- 模型生成 Thought 与 Action 指令；外部控制器执行 Action，工具或环境返回 Observation。
- Observation 是观察，不等于完整真实状态。只读搜索可获得新信息而不改变被检索的事实。
- CoT 基线移除了外部行动与观察；Act-only 基线移除了显式 Thought，不能由此断言模型内部完全没有推理。
- Thought 改变后续上下文，不产生新的环境观察。

## 2. Wikipedia 接口

- search[entity]：实体页存在时返回该页前五句话；找不到时返回五个相似实体建议，不是“搜索前五个结果的第一个”。
- lookup[string]：在当前页面继续查找，返回下一句含指定字符串的句子。
- finish[answer]：提交答案并结束任务。

依据反馈改写查询的方向正确。“多次失败返回空”不是论文的统一恢复规则；原文组合策略中，ReAct 超过规定步数未返回答案时回退到 CoT-SC。工程中也可设计明确的信息不足或预算耗尽状态。

## 3. 实验任务与指标

| 任务 | 本文环境与目标 | 本文指标 |
| --- | --- | --- |
| HotpotQA | Wikipedia 多跳问答 | 最终答案 Exact Match，不是检索准确率 |
| FEVER | 对声明作支持、反驳、信息不足三分类 | 分类准确率 |
| ALFWorld | 文本交互的模拟家居环境 | 任务成功率 |
| WebShop | 使用真实商品资料的研究购物环境 | 平均属性满足得分、满足全部要求的成功率 |

WebShop 中不会真正下单付款，不能把结果直接推广为真实电商交易的可靠性。

## 4. 幻觉评价与切换条件

论文在 HotpotQA 中按答案 EM 判断正确与错误，从 ReAct、CoT 的两类轨迹中各随机抽 50 条，合计 200 条，人工检查推理与事实并分类。Table 2 的各项比例以对应分组为分母：

| 人工分类 | ReAct | CoT |
| --- | --- | --- |
| 答案正确组中仍含编造推理或事实 | 6% | 14% |
| 答案错误组中被归为幻觉失败 | 0% | 56% |

因此不能将 0% 理解为 ReAct 消除了幻觉，不能将分组比例当成整体幻觉率。最终答案正确也不保证过程正确。

两种切换均是启发式控制条件：

- ReAct → CoT-SC：规定步数内没有返回答案；HotpotQA 为 7 步，FEVER 为 5 步。
- CoT-SC → ReAct：n 个采样答案中，出现次数最多的答案严格少于 n/2 次。并非主观判断是否需要检索，也不要求所有答案一致。

## 5. 训练与循环问题

主体 few-shot prompting 冻结参数，使用人工编写的少量成功轨迹作上下文演示。初步微调使用模型生成且最终答案正确的约 3,000 条轨迹训练较小模型；最终答案正确不自动保证轨迹内每个事实均正确。

重复 Thought/Action 是原文观察到的推理错误模式。第 6 页脚注 4 怀疑次优贪心解码可能相关，但没有解码消融证明因果，不能据此声称换成采样或 beam search 就解决。表中的 47% 是整个推理错误类别的比例，不是循环单独占比。

### 工程补充：显式检测与恢复

以下为基于讨论的设计建议，不是论文已经验证的解决方案：

1. 记录工具名、规范化参数、观测摘要和相关子目标或环境状态；在窗口内检查是否重复且没有获得新信息或状态变化。不能仅凭 Thought 文本重复或调用次数就判死循环。
2. 触发后暂停相同操作，向模型反馈停滞事实，要求改写查询、选择另一种已有工具策略或明确报告信息不足。
3. 同时设置总步数、时间或成本预算；预算到达则终止并如实记录未完成状态。
4. 检索恢复可利用相似实体、别名与新线索改写查询，再使用 Lookup 定位证据；无新依据时避免无限重试。
5. 长上下文可保留目标、约束、已确认事实、失败路径、待办和证据位置的摘要，详细日志外置并按需检索。
